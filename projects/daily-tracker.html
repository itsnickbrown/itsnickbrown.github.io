Forecasting

Daily POS tracker and month-end projection

A one-click morning update that scrubs distributor files, updates the ledger and redraws the tracker. The projection paces the month against how that month normally books.

The problem

The corporate POS report came out monthly. By the time it landed, the month was over. I wanted to know mid-month whether we were on pace, and which partners had bought since yesterday.

What I built

A batch file runs the chain each morning:

python pos_scrubber.py --folder .     # detect each distributor file, match resellers, flag new names
python tracker.py                     # read snapshots, update charts and KPIs
start partner_tracker.html

The scrubber auto-detects which distributor a file came from, fuzzy matches reseller names, applies the named-account exclusion and flags names it has never seen. The tracker then shows daily new revenue, MTD by month, partners added through the month, and the top purchases.

The projection

A flat run rate is wrong most months. July back-loads: its last few days can be a third of the month. August front-loads. So the projection divides month-to-date revenue by the share a normal month has booked by the same business day. The curve per month comes from five years of history.

share = curve[min(elapsed, len(curve)) - 1]
projection = mtd / share if elapsed >= 3 else None   # too early to trust

Monthly forecast workbooks carried bear, base and bull cases. When a month slowed in the back half, I lowered the base case.

How AI fit in

Claude helped write the scrubber and the tracker. The judgment calls were mine: when to distrust a number, how to handle credits, when a projection has too few days behind it to show.
